# GetAround — Car Rental Price Prediction API

**FastAPI** service that predicts the optimal daily rental price of a car from its
characteristics.

The model is a complete scikit-learn pipeline, trained by `model/train.py` and
shipped here as a `model.joblib` file. This service only loads it at startup and
exposes it behind an HTTP route — no training happens here.

**Production URL:** https://alexbarbier-getaround-api.hf.space

## Endpoints

| Method | Route | Purpose |
|---|---|---|
| GET | `/` | welcome message + link to the docs |
| GET | `/health` | service state (model loaded? which scikit-learn?) |
| POST | `/predict` | predicts a price from a car's characteristics |
| GET | `/docs` | **interactive documentation**, generated by FastAPI |

## Folder contents

```
api/
├── app.py           # FastAPI definition (routes + Pydantic schema)
├── test_app.py      # 9 tests: contract, validation, unknown categories
├── model.joblib     # serialised scikit-learn pipeline
├── requirements.txt # Python dependencies
├── Dockerfile       # runtime environment
├── .dockerignore    # files excluded from the build context
└── README.md        # this file (its YAML header configures the Space)
```

This folder is **self-contained**: it depends on no file from `model/` or
`dashboard/`. That is what makes it pushable as-is to a Space.

# Running it

Three ways, from the lightest to the closest to production. They are not
alternatives: steps 1 and 2 are how you validate before deploying at step 3.

## 1. Locally, without Docker

Fastest for development. Requires Python 3.11 and an activated virtual environment.

```bash
cd api
pip install -r requirements.txt
uvicorn app:app --reload
```

The API listens on **http://localhost:8000** — interactive docs at
http://localhost:8000/docs.

> **`uvicorn app:app`** — the first `app` is the module (`app.py`), the second is
> the `app = FastAPI()` variable defined inside it.
>
> **`--reload`** restarts the server on every file change. Convenient in
> development, **never to be used in production** (memory overhead and
> unpredictable behaviour under load).

## 2. Locally, with Docker

Reproduces the Space environment exactly. This is the dress rehearsal: if this
step passes, the deployment will too.

```bash
cd api
docker build -t getaround-api .
docker run -p 7860:7860 getaround-api
```

The API listens on **http://localhost:7860** — docs at http://localhost:7860/docs.

> **Why 7860 here and 8000 above?** Hugging Face Spaces expects the application to
> listen on the port declared in the `app_port` YAML header — 7860 by convention.
> The `Dockerfile` therefore pins that port in its start command:
>
> ```dockerfile
> CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "7860"]
> ```
>
> Same command as step 1, without `--reload`, and with `--host 0.0.0.0` so the
> server accepts connections from outside the container (uvicorn listens only on
> `127.0.0.1` by default, so the Hugging Face proxy could not reach it).
>
> The `-p 7860:7860` maps that container port to the same port on your machine.

## 3. Deploying to Hugging Face Spaces

1. **Create a Space → SDK: `Docker`.**

   The "SDK" tells HF how to run the application. The Streamlit, Gradio and Static
   modes are shortcuts for standard cases. Choosing `Docker` means "assume
   nothing, read my Dockerfile and follow it" — which is what we want here, since
   the Dockerfile already describes the intended environment precisely (Python
   3.11, pinned dependencies, uvicorn).

2. **Push the *contents* of `api/`** to the root of the Space — not the folder
   itself. This README and its YAML header must end up at the root, and
   `model.joblib` must be present.

   ```bash
   git clone https://huggingface.co/spaces/AlexBarbier/getaround-api
   cd getaround-api

   git lfs install
   git lfs track "*.joblib"          # before adding the model

   cp -r ../Projet_GetAround/api/. .

   git add -A
   git commit -m "Deploy GetAround pricing API"
   git push
   ```

   ```powershell
   git clone https://huggingface.co/spaces/AlexBarbier/getaround-api
   cd getaround-api

   git lfs install
   git lfs track "*.joblib"

   # -Force on Get-ChildItem so dotfiles such as .dockerignore are included:
   # Copy-Item with a * wildcard skips them silently.
   Get-ChildItem ..\Projet_GetAround\api -Force |
       Copy-Item -Destination . -Recurse -Force

   git add -A
   git commit -m "Deploy GetAround pricing API"
   git push
   ```

3. **The Space builds the image and starts the container.** The status turns
   *Building*; the **Logs** tab shows the `docker build` output if it fails. Once
   *Running*, the API is served on port 7860 at the Space's public address.

# Calling the API

The same request works at all three steps above; only the base URL changes.

| Step | Base URL |
|---|---|
| 1. local, no Docker | `http://localhost:8000` |
| 2. local, Docker | `http://localhost:7860` |
| 3. deployed Space | `https://alexbarbier-getaround-api.hf.space` |

The easiest first try is to open `/docs` in a browser: FastAPI generates a form
there that sends a request without writing a line of code.

## With PowerShell

```powershell
$body = @{
    model_key = "Citroën"
    mileage = 140000
    engine_power = 100
    fuel = "diesel"
    paint_color = "black"
    car_type = "sedan"

Invoke-RestMethod -Uri "https://alexbarbier-getaround-api.hf.space/predict" `
  -Method Post -Body $body -ContentType "application/json"
```

`model_loaded` confirms `model.joblib` was found and deserialised at container
startup. `sklearn_version` matters just as much: a `.joblib` only deserialises
reliably under the version that wrote it, so this is the first thing to check when
a deployment misbehaves.

# Input validation

Two independent layers, in this order.

**Shape**, handled by Pydantic from the `CarFeatures` schema: the thirteen fields
must be present, correctly typed, and within plausible bounds (`mileage` between 0
and 1,000,000, `engine_power` between 1 and 1000). A malformed request gets a
**422** listing exactly what is wrong, before the model is ever consulted.

**Content**, handled by the API itself: categorical values are checked against the
categories the model was actually fitted on.

That second layer closes a silent failure found while testing. The encoder is
fitted with `handle_unknown="ignore"`, which keeps the service from crashing on an
unseen category — but encodes it as all-zeros and scores it anyway. `"Citroen"`
without the diaeresis returned a confident **123.92 €** instead of 115.60 €: a
200, a plausible price, and no way for the caller to know the request had been
misread.

The API now reads the accepted values back from the fitted encoder inside the
loaded artifact — never from a hard-coded list, so the check follows the model
when it is retrained — and rejects unknown values:

```json
{
  "detail": [
    {
      "loc": ["body", "model_key"],
      "msg": "Unknown value 'Citroen'; the model was not trained on it.",
      "type": "value_error.unknown_category",
      "allowed_values": ["Audi", "BMW", "Citroën", "..."]
    }
  ]
}
```

Same 422 and same detail shape FastAPI already returns for schema errors, so a
client that handles those needs no extra branch. `allowed_values` is the addition:
a caller who mistyped a brand can fix it from the response alone.

# Known limitations

**No prediction interval.** The API returns a point estimate and does not quantify
the uncertainty around it, although that uncertainty varies with how much training
data sits near the requested profile.

**Model frozen in the image.** `model.joblib` is copied into the Docker image at
build time. Updating the model means rebuilding and redeploying the Space; there is
no hot reload and no prediction versioning. This is deliberate — it keeps the API
independent of MLflow, Neon and S3, so it keeps serving if the tracking stack goes
down — but it is the constraint a model registry would remove.

**No authentication, no rate limit.** `/predict` is public and unthrottled.
Acceptable for a demonstration, not to be kept as-is in production.

**Stateless container.** The Space persists nothing between restarts. Harmless
here, since the API only reads the model, but any file writing would be lost.

**Categorical guard degrades silently if the artifact is unexpected.** If the
loaded pipeline contains no locatable `OneHotEncoder`, the validation above is
disabled and a warning is logged at startup. Refusing to start would be the right
call for a model fetched at runtime; here the artifact ships inside the image and
is covered by the tests, so that branch is unreachable in practice.

# Possible extensions

- **Expose the reference values** through a `GET /model-keys` endpoint, so callers
  can discover the accepted categories without triggering a 422 first.
- **Return a prediction interval** rather than a point estimate, for instance from
  the spread of the individual trees' predictions.
- **Log incoming requests** to track drift against the training distribution and
  trigger a retrain when the gap becomes significant.
- **Protect access** with an API key and apply rate limiting.
- **Decouple the model from the image** by loading it from a registry at startup,
  so the model can be updated without redeploying the API.
